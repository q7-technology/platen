The before

Nobody sets out to print labels badly

It just accretes. A template someone made in Word, a laptop with the driver on it, and a batch number typed in by hand at four in the afternoon.

“The template is a Word doc. Someone changes the batch number and saves over it.”

Every label is a chance to get it wrong.

“Only Dave can print. The driver's on his laptop and he's on leave.”

A printer wired to one desk is a single point of failure.

“We found out the expiry was wrong when the pallet came back.”

By then it's a recall conversation, not a printing one.

None of those are printer problems. They're data problems that happen to end up on paper.

How it works

Four steps, and then nobody thinks about it again

01

Draw the label

Drag text, barcodes, QR codes and images onto a canvas measured in real millimetres at your printer's dot pitch. Already have ZPL? Import it and edit from there.

02

Point it at your data

Postgres, SQL Server, MySQL, SQLite or a REST endpoint. Save a query with parameters, and Platen works out which columns are text, numbers, dates and images.

03

Bind the fields

Drop a column into a barcode and it prints that column. Base64 image columns become real printed graphics. No scripting, no expressions to debug.

04

Let the floor print

Pick a template, answer the two questions the query asks, press the button. Twelve labels, one job, no driver on anyone's laptop.

What you get

Built for the awkward bits

A canvas in millimetres

What you draw is what comes out, at 203, 300 or 600 dpi. Rulers, snapping, and a live preview rendered from real rows — including the dithering, so there are no surprises on paper.

Bind to what you already run

Read-only connections and prepared statements — Platen never issues anything but a SELECT. Parameters you mark as “ask at print time” become the questions the operator answers.

The symbologies that matter

Code 128 with automatic subsets, GS1-128 for pallets, Code 39, Interleaved 2 of 5, QR and Data Matrix — with human-readable text where the auditor wants it.

Images out of your data

A base64 column — a compliance mark, a signature, a staff photo — is decoded, scaled to the printer's dots, dithered and sent as a graphic. The one thing most label tools make you give up on.

Printers, however they're wired

Raw TCP on port 9100 for anything on the network, a small agent for a USB unit on someone's desk, or the CUPS queue you already have. No drivers to install, anywhere.

Jobs you can answer for

Every run is queued, retried and cancellable between labels — not between batches. Warnings travel with the job, so “why did that one come out blank” has an answer a week later.

Under it

It speaks the printer's own language

Platen renders ZPL directly and writes it to the printer. Nothing is rasterised into a picture of a label, so barcodes stay crisp at any dot pitch and a 100 × 150 mm label is about 6 KB on the wire.

Millimetres in, dots out — the conversion happens once, on the server, against the printer's real dpi.
Every label in a run is rendered before the first one prints, so a broken binding is a sentence on screen, not half a roll of ruined stock.
Runs on your server, your VPS or ours — it's a Python service, Postgres and Redis. Nothing exotic to look after.

Before you ask

The questions everyone asks

Do we have to buy new printers?
No. If it takes ZPL — over the network on port 9100, over USB, or through a CUPS queue — it works. That covers most Zebra desktop and industrial units, and a fair few compatible printers from other makers.
Does it write to our database?
Never. Connections are made as a read-only role and every query runs as a prepared statement, so the values an operator types can't become SQL. If your DBA wants to see the exact grants, we'll send them.
What happens when the internet drops?
The queue holds the job and the printer agent keeps whatever it has. Nothing is silently lost, and because a run is cancellable between labels rather than between batches, stopping means stopping now.
Can we keep the label designs we already have?
If they're ZPL, import them and carry on editing from the canvas. If they're a Word document or a PDF someone made years ago, we'll rebuild them during onboarding — that's usually an afternoon.
What's the licence, exactly?
MIT. Use it commercially, fork it, rebrand it, bundle it into something you sell — the only condition is that the copyright notice travels with it. There is no open-core split and no feature held back for a paid tier: the hosted service runs the same code that's in the repository.
Where does it run?
Your choice. On our infrastructure, on a VPS you own, or entirely inside your network if the database can't leave the building. It's a Python service, a Postgres database and a Redis queue.
